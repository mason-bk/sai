# 사이 - 둘이 쓰는 가계부

부부 두 사람이 아이폰 홈 화면에서 쓰는 가계부 웹앱(PWA)입니다. 기록 원본은 각자 소유한 구글 시트에 있고, 이 저장소에는 화면 코드만 있습니다.

- 앱 주소: https://mason-bk.github.io/sai/
- 이 저장소에는 시트 주소·키·거래 데이터가 없습니다. 처음 실행할 때 기기마다 설정 코드를 넣어 연결합니다.

## 구조

```
아이폰 홈 화면 앱 (이 저장소, GitHub Pages)
   │  text/plain POST (CORS 사전요청 없음), 설정 코드 속 키로 인증
   ▼
Google Apps Script 웹앱 (doPost JSON API, 비공개)
   │  LockService로 동시 쓰기 직렬화, 최신 수정 우선 병합
   ▼
Google Sheet (Transactions 원장 + 보기용 탭)
```

| 파일 | 역할 |
|---|---|
| `index.html` | 화면 구조와 스타일(색·글자·간격·모션 토큰, 라이트/다크, 폭 3구간 레이아웃) |
| `app.js` | 화면: 홈(다가오는 결제·장부 기준 카드값·결제자별 몫·명세서 대조·분석 펼침)·내역·기록 시트·정기·설정·가져오기 확인 목록, 화면 모드, 스와이프 삭제 |
| `store.js` | 데이터 층: 기기 저장(localStorage), 오프라인 대기열, 서버 동기화, 설정 코드 연결. 서버를 바꿀 때 이 파일만 교체 |
| `core.js` | 순수 로직: 결제 주기, 결제일·다가오는 청구·카드값·결제자별 몫·명세서 차이, 카드 알림 해석, CSV·엑셀 열 추정, 중복 대조, 필터·합계. 화면·저장소와 무관(Node에서도 실행) |
| `sw.js` | 서비스 워커. 앱 화면만 캐시(네트워크 우선). 거래 데이터는 캐시하지 않음 |
| `manifest.webmanifest`, `icons/` | 홈 화면 설치 정보와 아이콘 |

## 주요 기능
- 금액은 정확하게: 직접 입력은 1 ~ 9,999,999,999원 정수만. 잘못된 값(11자리·음수·소수·지수)은 자르거나 숫자만 남기지 않고 그대로 둔 채 저장을 막음(화면과 데이터 층 두 번 검사)
- 어느 폭에서도: 좁은 폰은 한 칸 + 아래 탭, 폴더블 펼침·태블릿 세로는 두 칸, 태블릿 가로·가로 폰은 옆 메뉴(같은 5개 목적지). safe-area 네 방향, 키보드, 글자 200% 대응
- 3초 입력: 금액 → 거래처 칩(분류·결제수단 자동 추천) → 아래 '기록하기'. 즐겨찾기는 누르면 오늘 날짜로 바로 저장(8초 되돌리기). 닫아도 작성 중 내용 보존
- 화면 모드: 기기 설정 / 라이트 / 다크 (이 기기에만)
- 카드 알림 붙여넣기: 문자·앱 알림 여러 건 → 확인 목록 → 한 번에 저장(취소는 환불, 이미 있는 기록은 표시)
- 파일로 빠진 기록 찾기: 카드 이용내역·다른 가계부 CSV·엑셀을 기존 기록과 대조해 빠진 것만 추가
- 홈(v24, 카드값 중심): 다가오는 결제일과 남은 날, 장부 기준 카드값(카드 결제수단 기록의 합, 카드사 청구 확정액 아님), 누가 얼마를 결제했나(결제자별 몫), 명세서와 금액 맞추기(청구 금액 입력 → 차이, 파일·알림으로 빠진 기록 찾기), 빠른 경로, 이번 청구의 마지막 기록, 예산·환불 대기·분류 요약. 카드 결제일과 카드값에 넣을 결제수단은 설정 → 카드 결제일(두 사람 공유). '분석 더 보기'에 1일 / 1주 / 1개월(카드 결제 주기) / 기간 지정, 분류·결제자 필터, 예산, 이전 기간 대비, 이번 주기 예상, 누적 흐름, 기간별 막대, 비율
- 내역: 기간·분류·결제자·결제수단·금액·종류·검색 필터와 결과 합계, 목록/달력, 왼쪽으로 밀어 삭제(확인 팝업 + 되돌리기)
- 달력(v23): 카드 결제 주기 한 벌을 연속 격자로(두 달로 나누지 않음). 주기 이동 화살표·라벨은 달력 머리에, 좌우로 밀어도 이동. 칸은 그날 순지출 약식(내림), 선택한 날 아래에 원 단위 합계·그날 기록·'이 날짜에 기록'
- 오프라인: 기기에 먼저 저장하고 연결되면 전송. 두 기기 동시 수정은 나중 수정 우선
- CSV 내보내기

## 업데이트 방법
1. 작업 브랜치에서 수정한다 (`main`에 직접 올리지 않음).
2. 로컬 모의 서버로 회귀 테스트(입력·동기화·오프라인·초안·스와이프·삭제·금액 계약)와 레이아웃 자동 점검(폰·폴더블·태블릿·가로·글자 200% × 라이트/다크 × 모든 화면, 겹침·잘림·44px·가림·safe-area 위반 0)을 통과시킨다.
3. `sw.js`의 `CACHE` 이름을 한 단계 올린다 (`sai-shell-vN`). 그래야 설치된 앱이 새 파일을 받는다.
4. `CHANGELOG.md`에 날짜와 변경 내용을 적는다.
5. `main`에 합치면 GitHub Pages가 1분 안에 배포한다.

사용자 쪽: 앱을 완전히 종료했다 다시 열면 새 버전이 뜬다. 아이콘 그림이 바뀐 경우만 홈 화면에서 지우고 다시 추가한다(이때 설정 코드 재입력).

## 공개 저장소 규칙
- 개인 정보(실제 카드사명, 가족 호칭, 시트 주소, 키, 거래 내역)를 기본값·예시·커밋에 넣지 않는다. 카드 알림 해석은 특정 카드사가 아닌 공통 패턴으로 만들고, 예시·테스트 데이터는 가짜로 쓴다.
- 사용자별 분류·결제수단·대상은 시트의 Settings에서 내려받는다.
